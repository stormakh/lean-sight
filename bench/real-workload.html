Findings

  • grafana-rs bug found and fixed (commit 58d9745): the first 30-minute run showed 2 of 20 grafana-rs viewers logged out for good at the 10-minute session token rotation. Cause: two concurrent rotate calls with the same cookie could both rotate the token, so a client could keep a token the server no longer knew. Rotation is now a conditional database update (one winner, as upstream). Race check, 16 concurrent rotates, 10 trials: 6 dead cookies before the fix, 0 after. This run uses the fixed build: 0 failed requests.
  • Real Grafana under concurrent logins: in a first attempt, 9 of 20 viewers that logged in within 10 s got HTTP 500 from Grafana ("database is locked (SQLITE_BUSY)", some after 13 s). The load generator now retries a failed login up to 5 times; in this run every login worked on the first try on both servers.
  • Token rotation on real Grafana: at each 10-minute rotation a few parallel requests get 401 before the session recovers (39 such responses in this run). grafana-rs had none.
  • One API difference: GET /apis/collections.grafana.app/v1alpha1/namespaces/default/stars answers 403 for a Viewer on Grafana and 200 on grafana-rs. The UI does not show an error either way.
  • Network bytes: grafana-rs sent 79 MB, Grafana 62 MB. grafana-rs does not gzip responses smaller than 1,400 bytes (many panel responses are near that size); Grafana gzips every response.
  • grafana-rs memory under load (32–37 MB) is per open connection: 20 viewers × 6 browser connections = about 120 connections, and grafana-rs runs one thread per connection (about 170 KB each while the connection is open). After the viewers left it went back to 7 MB. Grafana stayed at about 966 MB.

Correctness and errors

  • Before the run, the 15 panel queries of the dashboard were sent to both servers with the same fixed time window: 15 of 15 responses byte-identical.
  • Requests: Grafana 58,142 (59 not 2xx: open /apis/collections.grafana.app/v1alpha1/namespaces/default/stars → 403; refresh /api/annotations → 401; refresh /api/ds/query → 401; rotate /api/user/auth-tokens/rotate → 401); grafana-rs 58,220 (0 not 2xx: none).
  • Process count: Grafana 15 processes (server plus plugin processes), grafana-rs 1.
  • Startup: grafana pid=3936968 startup_ms=9153; grafana-rs pid=3937815 startup_ms=22.
  • Prometheus (shared by both) used 19.3% of one core during the load.

Memory is PSS of each server's whole process tree, sampled every 5 s. CPU is user + system time of the tree. Latency is measured by the load generator (bench/realload.mjs), per request, over keep-alive connections, up to 6 per viewer (as Chrome).
