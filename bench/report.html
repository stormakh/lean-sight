Goals (frozen before any Rust code): 20X less memory and 30X less CPU than default Grafana. All are met.

1. Resource use

Same machine, same script (bench/baseline.sh): fresh start, seed 1 Prometheus data source and 1 dashboard with 4 panels, 2 min warm-up, 5 min idle, then 5,000 requests per workload at 16 concurrent. Memory is PSS of the whole process tree. CPU is user + system time of the tree, divided by requests. Prometheus' own CPU is not counted on either side. Both servers gzip answers (Grafana's default enable_gzip = true).

Where Grafana's memory goes: the main server is about 400 MB, and 14 data-source plugin processes (Postgres, Loki, CloudWatch, and others) use 30–45 MB each, even with no such data source configured. "Trimmed" turns those plugins, alerting, live and plugin installs off; it saves memory but not CPU per request.

2. Does it behave like Grafana?

  • Real UI in Chrome (the unchanged Grafana 13.3.1 frontend against grafana-rs): home, dashboard with 4 live Prometheus panels, dashboard list and search, data source edit and "Save & test" ("Successfully queried the Prometheus API"), panel edit, Explore, create and save a new dashboard. No console errors; every API call answered 200.
  • Replay of recorded real-Grafana traffic with a strict scorer (exact JSON text and key order, exact large integers, full HTML pages, Content-Type and Location headers, typed rules for times and generated ids; 90 named rules, each with a reason):
    • UI tour, 165 calls: 162/165. The 3 that differ are /api/gnet/* (grafana.com catalog): grafana-rs answers 502, as Grafana does when grafana.com is not reachable.
    • API flows, 77 calls (login, users, data sources, Prometheus queries incl. errors, folders, dashboard versions and conflicts, annotations, query history): 77/77.
  • Upstream Prometheus plugin tests (grafana-prometheus-datasource v13.2.6, pkg/promlib) ported one by one, with the 72 golden files byte-identical to upstream: 328/328 pass. Cases not ported are listed with reasons in tests-data/not-ported.md.
  • Independent review by GPT Sol 6.1 (read-only) found the first scorer too weak. The scorer was made strict; it then found 4 real bugs (template comments, Content-Type charset, version time zone, Advisor ids), all fixed. It found no code that special-cases the recorded ids.

4. Known differences from Grafana

  • Dashboards with schema version below 39 are not converted on the server; the UI converts them itself, so they still work.
  • Search returns the same order as Grafana's bleve index, but the score, maxScore and queryCost numbers are our own (approved, checked difference).
  • Permissions come from the org role only (Viewer, Editor, Admin). Every save adds 1 to the dashboard version, even with no change. Deleted dashboards are gone (no "recently deleted").
  • Queries of one request run one after the other (Grafana runs them in parallel). Prometheus is called without gzip.
  • A successful basic-auth check is cached 60 s; no login rate limit. Secrets use our own AES-GCM format. Live is off.
  • The data source proxy is a plain forward (no plugin routes, OAuth pass-through, or cookies).

5. What these numbers do not prove

  • One small workload: 1 data source, 2–4 dashboards, 1 user. Many users, thousands of dashboards, or long runs (hours) were not tested. Throughput is limited by one SQLite connection.
  • CPU per request has 10 ms tick resolution over 5,000 requests (health is 17 ticks in total).
  • Only Prometheus 3.16.0 without auth was tested live. Basic auth, custom headers, warnings and native histograms were tested only through upstream golden files.
  • The UI was tested in one browser, as anonymous Admin. Viewer and Editor boot data were compared with captures from real Grafana, not clicked through.
  • Machine load varied during the day (other agents' builds); the Grafana and grafana-rs runs were not interleaved.

6. How it was built

Following ~/code/baileys-rs/PORTING-PLAYBOOK.md: freeze the baseline and the recordings first, write the contract (PORTING.md), build the foundations, then 3 agents in parallel git worktrees (A: boot, auth, users · B: dashboards, folders, search · C: data sources and Prometheus), then an independent review and a hardening pass. The core crates (json, crypto, http, grafana) compile with Lust 0.2.0; SQLite and the binary use Cargo only.
